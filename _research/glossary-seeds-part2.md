# Glossary seeds — Part II (Chapters 5–8)

Seed entries for the book's `glossary.md`, one line per term introduced or
load-bearing in Part II. Format: `### term — one-line definition (Ch N)`.
Part I terms (GPU, kernel, SIMD group, KV cache, GGUF, MTLBuffer, …) are
owned by Chapters 1–4 and not repeated here; Part II chapters cross-link to
them. Anchors are lowercase-hyphenated per the book's convention.

### weight — one learned coefficient of the model, multiplied in during the forward pass; Muse Glimmer has ≈27.9 B of them by tensor count (Ch 5)
### f32 — IEEE 754 32-bit float: 1 sign + 8 exponent + 23 mantissa bits, ~7 decimal digits (Ch 5)
### f16 — IEEE 754 16-bit float ("half"): 1 sign + 5 exponent + 10 mantissa bits, ~3 decimal digits, range 2⁻¹⁴ to 65,504 (Ch 5)
### quantization — storing each weight in fewer bits than its float format, accepting a small controlled error for a large byte reduction (Ch 5)
### codebook — the small table of allowed values a quantized index selects from; 4 bits select 16 entries (Ch 5)
### nibble — four bits, values 0–15; two pack into one byte, low nibble first in every format in this book (Ch 5)
### quantize — the inverse mapping: pick the codebook entry (index) closest to the original value (Ch 5)
### dequantize — reconstruct an approximate value from a stored index: `scale × index + min` (or a float-LUT lookup) (Ch 5)
### quantization error — the gap between the original value and its reconstruction; bounded by scale/2 for nearest rounding (Ch 5)
### dot product — the multiply-and-add pairing of two equal-length vectors into one scalar; the atom under every weight matrix (Ch 5)
### block — a small contiguous group of weights sharing one scale (and optionally a min); the unit of local quantization (Ch 5)
### scale — the local step size of a block's codebook, stored in floating point because it must span wide magnitude ranges (Ch 5)
### min — the offset where an asymmetric block's codebook starts; `value = scale × index + min` (Ch 5)
### min+offset — the asymmetric-quantization trick: spend one extra stored number per block to place the grid exactly where the data lives (Ch 5)
### symmetric quantization — one number per block (a scale), codebook spanning ±scale·max, zero maps to zero; cheapest, wastes range on offset blocks (Ch 5)
### asymmetric quantization — two numbers per block (scale + min); handles blocks not centered on zero at the cost of the extra stored min (Ch 5)
### DC offset — a block mean far from zero; halves a symmetric grid's effective precision, the case min+offset exists for (Ch 5)
### bitrate — bits per weight of a stored format: payload bits plus header bits ÷ block size (Ch 5)
### overhead — the per-block header bytes (scales, mins) amortized over the block's elements; what block size trades against local range (Ch 5)
### super-block — kquant's 256-element storage unit (Q4_K: 144 bytes, Q5_K: 176, Q6_K: 210) (Ch 5, Ch 6)
### sub-block — the 32-element (K4/K5) or 16-element (K6) group inside a super-block carrying its own scale/min (Ch 6)
### kquant — llama.cpp's K-quant family of block-quantized integer formats; Muser's reference-lane weights, mixed per tensor (Ch 6)
### Q4_K — 144 bytes per 256 elements (4.5 bits): two f16 super-scales, 8× 6-bit packed sub-scales/mins, 128 bytes of nibbles; min+offset (Ch 6)
### Q5_K — 176 bytes per 256 elements (5.5 bits): Q4_K plus a 32-byte high-bit plane (Ch 6)
### Q6_K — 210 bytes per 256 elements (6.5625 bits): signed 6-bit codes split across ql/qh planes, 16 int8 sub-scales, f16 super-scale last (Ch 6)
### matvec — matrix-by-vector multiply: one dot product of a weight row against the input vector per output element; decode's every projection (Ch 6)
### access pattern — what memory a kernel reads, in what order, how much; "where the bandwidth story lives" (Ch 6)
### dispatch ladder — the ordered kernel choices per (dtype, token-count) in `encode_quantized_matmul`, kept source-pinned against llama.cpp (Ch 6)
### NVFP4 — NVIDIA's 4-bit float weight format: E2M1 payloads, one E4M3FN scale per 16 values, one f32 scale2 per tensor; exactly 4.5 bits/weight (Ch 7)
### E2M1 — the 4-bit float codebook: 1 sign + 2 exponent + 1 mantissa; values ±{0, 0.5, 1, 1.5, 2, 3, 4, 6} with relative spacing (Ch 7)
### E4M3FN — the 8-bit float block scale: finite-only (NaN at 0x7f/0xff), max magnitude 448, exponent bias 7 (Ch 7)
### scale2 — the per-tensor f32 multiplier applied last in NVFP4's pinned order `(e2m1 × e4m3fn) × scale2` (Ch 7)
### companion tensors — the bound `.nvfp4_scale`, `.nvfp4_scale2` (and optional `.nvfp4_input_scale_inv`) tensors every NVFP4 weight matrix must carry, validated fail-closed at load (Ch 7)
### native lane — the product lane: Mac decodes NVFP4 weights directly, FP16 KV, F16 LM head, remote NVFP4 prefill (Ch 7)
### W4A16 — weight-only NVFP4 mode: 4-bit weights, wide activations quantized per 256-value super-block to a Q8-K-style grid; the selected product artifact (Ch 7)
### W4A4 — weights and activations both 4-bit (FP4 groups of 16, gated by `input_scale_inv`); on the Mac, qualified for batch parity only (Ch 7)
### input_scale_inv — the optional scalar whose presence selects W4A4 arithmetic; must pair with `muser.activation_precision=nvfp4` or the load fails (Ch 7)
### integer-exact contraction — decoding E2M1/E4M3FN as Q1/Q9 integers so the block dot is an order-free i64 sum with a fixed 2⁻¹⁰/2⁻²⁰ denominator (Ch 7)
### half-bit embedding — decoding eight E2M1 codes as f16 bit patterns scaled by 2⁻¹⁴ and folding 2¹⁴ into the block scale; MLX-lineage trick (Ch 7)
### Fallback B — the shipping disposition: native NVFP4 serves plain decode, speculation stays kquant-only, and `producer_mode: native` refuses DFlash at startup (Ch 7)
### Nvfp4ProducerMode — receiver config enum `Exact | Native` selecting the producer's numeric contract; modes keep separated cache identities (Ch 7)
### draft model — the small model that proposes tokens cheaply for a large target to verify; pure overhead that pays when its guesses are accepted (Ch 8)
### target — the full model whose exact distributions decide every accepted token; the draft never decides (Ch 8)
### speculative decoding — draft k tokens, verify all k+1 rows in one target batch; exact because acceptance is decided against full target distributions (Ch 8)
### DFlash — Muser's five-layer kquant draft assistant, fed pinned target hidden states via a 33,280→6,656 fc projection (Ch 8)
### context geometry — the enrolled sink+window shape (`DFlashContextGeometry`) bound to the draft's digest; receivers must never infer it locally (Ch 8)
### sink — the pinned first 64 rows of the DFlash context cache (`DFLASH_CONTEXT_SINK_SIZE`), part of the ABI, not GGUF metadata (Ch 8)
### verify length — proposals per round: exactly 3, 7, or 15; harness pins 15, serving froze 7 for natural-text robustness (Ch 8)
### acceptance rate — accepted proposals ÷ drafted proposals; gated per-request over a recent 8-round window with a 0.25 floor (Ch 8)
### draft trace — the deterministic per-round proposal list (`draft_token_trace`) that qualification compares exactly (Ch 8)
### transactional checkpoint — the pre-round KV snapshot (`MetalSpeculativeCheckpoint`): NoPE rewind is metadata-only, SWA rings retain the ≤16 rows a block may overwrite (Ch 8)
