# Glossary seeds — Part IV, chapters 11–16 (kernel chapters)

One line per term introduced or first-defined in chapters 11–16, for merge
into `glossary.md`. Format: `### term — one-line definition (Ch N)`.

### embedding — a learned lookup table with one row per vocabulary token; "embedding a token" means reading its row (Ch 11)
### embedding table (`token_embd.weight`) — the `[hidden_dim × vocab_size]` GGUF tensor, Q4_K (3,744 B/row) or F16 on Muser's lanes (Ch 11)
### vocab / vocab_size — the set (and count) of token ids; 202,048 for Muse Glimmer (Ch 11)
### gather — reading many table rows at once indexed by an id array; decode's embedding is a gather of batch width 1 (Ch 11)
### untied embeddings — input embedding and output LM head are separate tensors of the same shape (both exist for Muse Glimmer) (Ch 11)
### entry norm — the first RMSNorm after the embedding, bound to an all-ones γ because the model has no entry-norm tensor (Ch 11/12)
### normalization — any op that pins a vector's magnitude to a predictable band so deep stacks of multiplies don't drift (Ch 12)
### LayerNorm — normalize by subtracting the mean and dividing by the standard deviation; two reductions (Ch 12)
### RMSNorm — normalize by dividing by √(mean(x²)+ε) then multiplying by γ; one reduction, Muse Glimmer's norm everywhere (Ch 12)
### rms / mean of squares — √((1/n)Σxⱼ²); equals the standard deviation exactly when the mean is zero (Ch 12)
### gamma (γ) — the learned per-channel weight applied after normalization; re-learns the shape the norm flattened (Ch 12)
### epsilon (ε) — the tiny constant inside the square root keeping the denominator positive; 1e-5 from the GGUF on Muse Glimmer (Ch 12)
### post_norm_eps (1e-8) — llama.cpp's hard-coded epsilon for the two sandwich post-norms; not carried in the GGUF (Ch 12)
### sandwich norm — the Gemma-2-style pre-norm → sub-block → post-norm → residual pattern; four norm sites per layer (Ch 12)
### dual-eps tail — the fused dispatch computing post-norm (eps 1e-8) + residual add + next pre-norm (eps 1e-5) in one kernel (Ch 12)
### rsqrt vs 1/sqrt — fast-math reciprocal sqrt vs the IEEE-rounded pair; a few ULP per call that compound across a token (Ch 12)
### norm-boundary fusion — merging separated norm-boundary dispatches; rejected in Muser's campaign for breaching logprob tolerance (Ch 12)
### matvec / GEMV — matrix×vector product: one dot product per output row; the decode-shape of every projection (Ch 13)
### GEMM — matrix×matrix product; the prefill shape of the same weights, where each weight byte serves a whole batch (Ch 13)
### dot product — Σ of element-wise products of two equal-length vectors; the similarity measure inside every matvec and score (Ch 13)
### row-major — weight layout where each output row's elements are contiguous in memory; makes one row one DRAM span (Ch 13)
### ggml kargs — llama.cpp's packed C struct of tensor extents/strides (`ne00`, `nb01`, …) its Metal kernels take instead of scalars (Ch 13)
### nr0 / rows_per_group — output rows each threadgroup reduces in the pinned matvec kernels; 2 for Q4_K/Q6_K, 1 for Q5_K (Ch 13)
### pre-decoded scales — decoding all 8 sub-block scale/min pairs once per super-block so the inner loop uses constants (Ch 13)
### fma — fused multiply-add, `a·b+c` with one rounding; the per-element dequant instruction of the 4r2s fallback (Ch 13)
### concurrent dispatch set — multiple independent kernels encoded in one closure so the GPU may overlap them (Q/K/V/gate) (Ch 13)
### batch-width boundary — the token-count at which the projection kernel changes; a floating-point reduction-order boundary kept llama-exact (Ch 13)
### pinned metallib (`MUSER_GGML_METALLIB`) — the prebuilt llama.cpp kernel library loaded as binary provenance for parity (Ch 13)
### positional encoding — any scheme baking token order into the vectors before attention, which is permutation-invariant without it (Ch 14)
### permutation-invariance — raw attention's property of producing the same scores under token reordering; why position must be injected (Ch 14)
### RoPE — rotary positional embedding: rotate Q/K pairs by position-dependent angles so Q·K depends only on position difference (Ch 14)
### rotation matrix — the 2×2 `[cos −sin; sin cos]` that spins one coordinate pair; RoPE's only arithmetic (Ch 14)
### theta / rope_base_swa — the base of the per-pair frequency table θᵢ = base^(−2i/head_dim), read from `rope.freq_base_swa` (Ch 14)
### interleaved (NORM) pairing — RoPE convention rotating adjacent pairs (x[2i], x[2i+1]); Muse Glimmer's convention (Ch 14)
### half-split (NEOX) pairing — RoPE convention pairing x[i] with x[i+head_dim/2]; Llama-family convention, wrong for this checkpoint (Ch 14)
### cached frequency table — the powf-built [head_dim/2] θ table uploaded once; kernels do one multiply, no pow (Ch 14)
### precise::cos / precise::sin — Metal's per-call high-accuracy trig, used at RoPE's large angles despite fast-math compilation (Ch 14)
### NoPE — the 13 full-attention layers ({3,7,…,51}) with no positional rotation at all; `layer % 4 == 3` (Ch 14)
### SWA layer — one of the 39 sliding-window layers (window 2,048) that carry RoPE (Ch 14)
### QK-norm — per-head 128-wide RMSNorm applied to Q and K after projection; parameterless here (constant broadcasts) (Ch 14)
### qk_scale_factor (≈3.87) — the uniform Q-norm gain the converter synthesized; folded into Q, independent of the 1/√128 softmax scale (Ch 14)
### QkNormProbe — the load-time proof that q/k norm tensors are constant broadcasts; a learned norm aborts startup (Ch 14)
### relocatable KV — NoPE cache bytes valid at any position (no rotation baked in); "relocate = memcpy" (Ch 14)
### KV cache — the store holding every visible past token's K and V per layer so attention never recomputes them (Ch 15)
### MetalKvPlane — the per-layer {key, value} f16 buffer pair plus explicit capacity/len/origin ring metadata (Ch 15)
### token-major layout — `[capacity][kv_dim]` storage keeping one token's two KV-head rows adjacent; the SWA ring's layout (Ch 15)
### head-major layout — `[kv_head][capacity][head_dim]` storage keeping each KV head's history contiguous; the NoPE plane's layout (Ch 15)
### ring — the fixed-capacity circular store where new rows overwrite the oldest; capacity = min(max_context, 2,048) on SWA layers (Ch 15)
### origin_logical / origin_physical — the explicit pair tracking which logical token sits at the front of the live window and in which physical slot (Ch 15)
### append — the fail-closed ring reservation: position must equal origin_logical+len, else CacheDiscontinuity (Ch 15)
### growing plane — the NoPE regime where capacity is max_context, the ring never wraps, and origin_logical stays 0 (Ch 15)
### ring rotation — where origin_physical points; must be preserved on restore because attention's float accumulation is scan-order sensitive (Ch 15)
### KV publication — the store dispatch that makes the current token's K/V visible to attention; a split closure per layer in production (Ch 15)
### attention — the one cross-token operation: score the query against each visible key, softmax, weighted-sum the values (Ch 16)
### query / key / value (Q/K/V) — what this token seeks / what each past token offers for matching / the payload it returns (Ch 16)
### score — the scaled dot product Q·K/√128 that measures a past token's relevance (Ch 16)
### softmax — exp-then-normalize turning scores into a probability distribution; bigger scores win smoothly (Ch 16)
### max-subtraction — subtracting the row max before exp; algebraically exact, prevents overflow to inf/NaN (Ch 16)
### online softmax — the running (max, sum, accumulator) formulation that never materializes the score array; rescales by exp(old−new) (Ch 16)
### partials `[M, S, O]` — the per-workgroup online-softmax state (max, denominator, weighted values) a reducer merges (Ch 16)
### GQA fan-in (32:2, 16:1) — 32 query heads share 2 KV heads; kv_head = head/16; the KV read is 16× smaller than full MHA (Ch 16)
### visible window — min(position+1, window) rows the kernel may read; SWA masks by addressing, never reading out-of-window tokens (Ch 16)
### route ladder — the four attention routes (llama vec / splitk / batch-store vec / ferrite interleaved) selected per layer per token (Ch 16)
### llama_vec_rows predicate — vec-route eligibility: metallib present, len>0, capacity≥32, and contiguous (unwrapped or full ring) (Ch 16)
### splitk — splitting the KV scan across workgroups/SIMD groups, each producing partials the reducer combines (Ch 16)
### current-token bypass — reading the current token's K/V as f32 from the activation buffers instead of the f16 plane; ferrite rung only (Ch 16)
### workgroup cap (nwg=32) — the split schedule's fixed 32 workgroups matching llama's launch; the admitted "depth-rent" vs higher occupancy (Ch 16)
### SWA staging — copying a wrapped ring into llama's padded absolute indices so the pinned kernel sees llama's exact reduction lanes (Ch 16)
