# Glossary seeds — Part IVb (Chapters 17–21)

One line per term introduced or load-bearing in chapters 17–21, for merge
into `glossary.md`. Format: `### term — one-line definition (Ch N)`.

### sigmoid — the logistic function σ(x) = 1/(1 + e^(−x)), mapping any real into (0, 1); the smooth on/off curve behind both Muse gates (Ch 17)
### attention-output gate — Muse Glimmer's learned per-channel multiplier: attn_out[i] ← attn_out[i] · σ(gate_proj[i]), applied in attention space before o_proj (Ch 17)
### o_proj (output projection) — the matvec mixing the 32 gated attention heads (4,096 wide) back into the 6,656-wide residual stream; Q4_K [4096→6656] per layer (Ch 17)
### read-modify-write — the hazard class of any in-place `x = x ∘ y` GPU statement; safe only when each thread owns disjoint elements and dispatches are ordered (Ch 17)
### gate activation buffer — the separate 16 KiB `σ(gate)` tensor an unfused gate would materialize; Muser's in-place kernel avoids it (Ch 17)
### FFN (feed-forward network) — the per-token, position-independent transform between attentions: widen 6,656 → 19,968, gate/activate, squeeze back; ~80 % of a Muse layer's weight bytes (Ch 18)
### SwiGLU — the gated FFN combination silu(W_gate·x) ⊙ (W_up·x): one projection decides whether a feature fires, the other what it carries (Ch 18)
### SiLU (Swish) — the activation x·σ(x): ReLU-like at the extremes, smooth, and slightly negative for small negative x (dips to ≈ −0.278 near x ≈ −1.28) (Ch 18)
### Hadamard product — element-wise vector multiply (a ⊙ b)[j] = a[j]·b[j], no cross-coordinate mixing (Ch 18)
### lockstep MAC — the fused-FFN pattern where one x load feeds both the gate and the up accumulator (and two rows) before touching memory again (Ch 18)
### fused gate+up route — `ffn_q4k_gate_up_silu_4r2s`, the opt-in (`MUSER_FERRITE_FFN_GATE_UP`) single-kernel SwiGLU widening; opt-in because its rounding differs from llama.cpp's node graph (Ch 18)
### unfused control route — the serving default FFN widening: two pinned ggml matvecs plus the pointwise `muser_silu_mul_inplace`, exact to the comparator's graph (Ch 18)
### down projection — the FFN exit matvec W_down · ffn_mid ([19968→6656]); carries both Q4_K (74.76 MB) and Q6_K (109.03 MB, +45.8 %) tensors on the release artifact (Ch 19)
### layer exit tail — the second fused dual-eps kernel per layer: residual += post_norm(delta) at ε 1e-8, then next layer's input = rms_norm(residual) at ε 1e-5 (Ch 19)
### 104 norm-boundary groups — the three separated-norm families (+51 entry +52 post-attention +1 post-FFN) of the +196-closure serving gap; their fusion is rejected for breaching the 1e-4 logprob contract (Ch 19)
### hybrid postmortem — the measured rejection record for aggressive norm fusion: logprob max error 3.197e-4 over contract, first divergence one f16 ULP in layer-1 V (Ch 19)
### logit — one raw f32 score per vocabulary token, before any probability or bound; Muse emits 202,048 per token (Ch 20)
### LM head (unembedding) — the largest matvec in the engine, `output.weight` [6656→202048] Q5_K ≈ 924.6 MB read once per token; the inverse role of the embedding (Ch 20)
### logit_scale — the 0.196116 multiplier applied to logits before the cap, read fail-closed from GGUF metadata `muse-glimmer.logit_scale` (numerically 1/√26) — not a code constant (Ch 20)
### soft cap — the order-preserving bound ℓ ← 20·tanh(ℓ × 0.196116 / 20): shrinks logit gaps, flattens softmax tails, leaves greedy argmax unchanged (Ch 20)
### four unary nodes — the serving soft cap as llama.cpp builds it: ×scale, ×1/20, tanh, ×20 as separately published kernels, chosen so public bytes match the comparator (Ch 20)
### one-shot bandwidth hit — a per-token (not per-layer) weight read, like the LM head's 924.6 MB: a flat slice of the budget, never a 52× multiplier (Ch 20)
### argmax — the reduction returning the index of the largest element; the winning index is itself the token id, so greedy decoding needs no softmax (Ch 21)
### greedy decoding — always emitting the highest-scoring token; deterministic, hence the only policy the exact-token parity gate can diff (Ch 21)
### sampling — converting logits to a (temperature-scaled, top-k/top-p filtered) distribution and drawing a token; needs the full vocab row, not just the winner (Ch 21)
### tree reduction — parallel reduction by stride-halving folds with a barrier per pass; log₂(n) steps inside one threadgroup (Ch 21)
### two-phase reduction — chunk the input (⌈202,048/1,024⌉ = 198 threadgroups), reduce each chunk to a (value, index) partial, then reduce the partials in one final threadgroup (Ch 21)
### deterministic tiebreak — strictly-greater comparison so equal logits keep the lower index, matching the CPU first-maximum convention; load-bearing for byte-identical diffs (Ch 21)
### full-distribution read-back — the serving route's per-token copy of all 202,048 logits (~789 KiB) to the CPU, the price of exact sampling, grammar re-rolls, and speculative acceptance (Ch 21)
### 4-byte read-back — the GPU-resident greedy chain's alternative: read only the argmax result slot per token (`dflash_argmax_results`, u32::MAX = fail-closed nonfinite flag) (Ch 21)
### Mt19937 — the in-tree bit-for-bit reimplementation of libc++'s std::mt19937 (llama.cpp's sampler RNG), so seeded results are stable across engines and Rust releases (Ch 21)
### sampler state — per-request RNG streams (distribution, XTC, mirostat, adaptive) plus scalars, snapshotted with sessions so a resumed request replays its exact draw sequence (Ch 21)
### GBNF — llama-style grammar format (Backus–Naur with charsets and token terminals) used for structured-output constraints (Ch 21)
### Earley recognizer — the chart parser behind the grammar matcher: keeps every ambiguous parse stack alive and consumes tokens byte-wise, accepting partial UTF-8 sequences (Ch 21)
### grammar rejection sampling — run the ordinary sampler first, check the winner against the grammar, re-roll with a mask only after rejection; the rejected draw still advances every RNG (Ch 21)
### EOG exclusion — masking the request's end-of-generation tokens inside the argmax reduction only, leaving stored logits byte-identical for logprob and session uses (Ch 21)
### speculative acceptance rule — accept a draft token with probability min(p/q, 1) against the full target distribution; on rejection, sample the renormalized max(p−q, 0) residual (Ch 21)
### exact speculative acceptance — Muser's CPU-side `verify_full_speculative_mt_ordered` contract: full target distributions plus the pinned RNG stream, gated by all-logit-row comparators (Ch 21)
