# Glossary seeds — Part III (Ch 9–10)

One line per term introduced/defined in chapters 9 and 10, for assembly into
`glossary.md`. Format: `### term — one-line definition (Ch N)`.

### transformer — an attention-plus-FFN block stack that maps a token sequence to a next-token prediction; the 2017 architecture of [arxiv:1706.03762] (Ch 9)
### token — an integer id standing for a word fragment; the model's input/output currency (Ch 9)
### layer (block) — one copy of the repeating unit: norm → attention → sandwich-norm residual → norm → FFN → sandwich-norm residual; Muse Glimmer has 52 (Ch 9)
### residual stream (hidden state) — the per-token vector every layer only ever *adds* to; `[6656]` f32 in Muse Glimmer (Ch 9)
### attention — the only cross-token mixer: each token's Query scores against past Keys (softmax-weighted) and pulls a weighted sum of Values (Ch 9)
### FFN (feed-forward network) — the per-token "thinking" sub-block; Muse Glimmer's is SwiGLU at width 19,968 (Ch 9)
### MuseConfig — the fully-resolved hyperparameter set parsed fail-closed from GGUF metadata; every field cited, no silent defaults (`config.rs:106`) (Ch 9)
### head_dim — the width of one attention head's Q/K/V vectors; 128 here, read from `attention.key_length` (not `hidden/n_heads` = 208) (Ch 9)
### attn_dim / kv_dim — query space `n_heads×head_dim = 4,096` vs KV space `n_kv_heads×head_dim = 256` (`config.rs:268-273`) (Ch 9)
### RMSNorm — `x / sqrt(mean(x²)+ε) ⊙ γ`; no mean subtraction; rescales the stream to ~unit magnitude (Ch 9)
### norm epsilon (ε) — the small constant under the RMS square root; 1e-5 from the GGUF for every norm except the two post-norms (Ch 9)
### sandwich norm — Gemma-2-style placement: each sub-block's *output* is normalized (post_attention_norm / post_ffw_norm) before the residual add (Ch 9)
### post_norm_eps — the 1e-8 epsilon of the two sandwich post-norms; a llama.cpp graph constant, NOT GGUF metadata (`config.rs:28`) (Ch 9)
### QK-norm — per-head RMSNorm (over each 128-vector) applied to Q and K before RoPE; eps 1e-5 (Ch 9)
### qk_scale_factor — ≈3.87 scalar broadcast into every Q-norm weight by the converter; folded gain on top of 1/√128 (Ch 9)
### QkNormProbe — load-time verification that q/k norm tensors are the converter's constant broadcasts; aborts on a learned norm (`loader.rs:98-138`) (Ch 9)
### GQA (grouped-query attention) — 32 query heads share 2 KV heads (16:1); shrinks KV bytes 16× vs full multi-head (Ch 9)
### query head / KV head — one of 32 independent 128-wide attentions vs one of 2 shared K/V providers (Ch 9)
### heads_per_kv — `n_heads / n_kv_heads = 16` query heads served by each KV head (`config.rs:274-276`) (Ch 9)
### SWA (sliding-window attention) — each query sees only the previous 2,048 tokens (`p1 − p0 < n_swa`); Muse Glimmer's 39 SlidingRope layers (Ch 9)
### NoPE (FullNoPe) — full causal attention with NO positional rotation at all; the 13 layers at indices 3,7,…,51 (Ch 9)
### MuseLayerKind — `SlidingRope` / `FullNoPe` enum; `uses_rope()` is true iff sliding (`config.rs:55-70`) (Ch 9)
### sliding_window_pattern — the GGUF period-4 key resolving `[sliding, sliding, sliding, full]`; missing key ⇒ panic, not a guess (Ch 9)
### KV ring — the fixed 2,048-row token-major KV plane of each SWA layer; bounded at 2 MiB per layer forever (Ch 9)
### NoPE growing plane — the 13 full layers' head-major KV plane that grows to max_context; rows are position-free bytes (Ch 9)
### relocate = memcpy — the NoPE consequence: a KV tile for positions [a,b) can be planted anywhere without recomputation — "the whole kvpack free lunch" (`lib.rs:9-10`) (Ch 9)
### RoPE (rotary positional embedding) — position injected by rotating Q/K coordinate pairs by position-dependent angles; SWA layers only, theta 500,000 (Ch 9)
### interleaved (GPT-J) pairing — RoPE convention pairing adjacent dimensions 2i and 2i+1 (vs half-split "NEOX"); the pinned checkpoint's convention (Ch 9)
### rope theta (freq base) — base frequency 500,000 (`rope.freq_base_swa`); larger theta ⇒ positions distinguishable over longer ranges (Ch 9)
### softmax — `exp(xᵢ)/Σⱼexp(xⱼ)`: turns attention scores into positive weights summing to 1 (Ch 9)
### causal mask — the rule forbidding a query from seeing keys at later positions (Ch 9)
### attention scale — `1/√head_dim = 1/√128 ≈ 0.0884` applied to Q·K scores, independent of the folded qk_scale_factor (`config.rs:279-281`) (Ch 9)
### sigmoid attention gate — Muse Glimmer's extra `[6656→4096]` projection; `attn_out ⊙ σ(gate)` applied between attention and o_proj (Ch 9)
### SwiGLU — gated FFN: `down(SiLU(gate·x) ⊙ (up·x))` over width 19,968 (Ch 9)
### SiLU — activation `x·σ(x)`, also called Swish (Ch 9)
### logits — raw per-vocab-entry scores, `[202,048]`, before scale/cap (Ch 9)
### logit scale — the 0.196116 (= 1/√26) multiplier applied to logits BEFORE the soft cap; GGUF metadata `muse-glimmer.logit_scale`, not a code constant (Ch 9)
### soft cap — `l → 20·tanh(l/20)`: confines logits to (−20, 20) without a cliff; changes what cross-engine logit comparison means (Ch 9)
### LM head — the final `output.weight [6656 × 202048]` projection to logits; a separate tensor from the embedding (untied) (Ch 9)
### untied embeddings — `token_embd.weight` and `output.weight` are two independent required tensors (`config.rs:294-298`) (Ch 9)
### GGUF — the single-file model container: metadata + tensors; the authority for all geometry and identity here (Ch 9)
### BPE tokenizer (merge-order aware) — GGUF byte-pair encoding respecting merge priority; vocab 202,048, identity bound by a metadata SHA-256 (Ch 9)
### chat template — the GGUF-embedded Jinja-style prompt renderer; pinned at exactly 7,167 bytes with its own SHA-256 (Ch 9)
### dual EOS — two end-of-generation control tokens (EOS 200,001 + EOT 200,008) merged into one stop set (Ch 9)
### prefill — feeding the whole prompt at once; many queries per weight ⇒ GEMMs, compute-bound (Ch 10)
### decode — one token in, one prediction out, repeated; single-vector matvecs, bandwidth-bound (Ch 10)
### GEMM — general matrix × matrix; the prefill-shape of every projection (Ch 10)
### matvec — matrix × vector; the decode-shape, reading each weight byte once for one multiply (Ch 10)
### speculative verify — the block-shaped third regime: the target scores up to `MAX_DFLASH_BLOCK = 16` drafted tokens in one pass (Ch 10)
### forward_into — the serving entry that routes one token to the batch graph and multi-token input to chunked prefill (`decode.rs:2077`) (Ch 10)
### one-row batch graph — the serving decode route: `forward_batch` with `token_count = 1`, chosen because it dispatches the exact pinned llama kernels (`decode.rs:2085-2091`) (Ch 10)
### public-logprob tolerance — the parity contract the legacy fused single-token graph breaches; the reason serving refuses it (Ch 10)
### encode_token — the legacy single-token 52-layer Metal graph; teacher-forced benchmark and phase-profile route (`decode.rs:5515`) (Ch 10)
### teacher-forced route — feeding known tokens through the exact one-token graph to match the comparator's no-readback policy (`decode.rs:2118-2137`) (Ch 10)
### encode_batch_hidden_range — the batch/serving encoder over a row range; mirrors `encode_token`'s op sequence (`decode.rs:3858`) (Ch 10)
### forward_decode_group — packed decode: 1..=4 sequences' tokens in one concurrent encoder, one commit, one wait (`decode.rs:4869`) (Ch 10)
### MetalShared — one executor per accelerator: context, kernels, mmap'd weights, scheduler; shared by all slots (`decode.rs:958`) (Ch 10)
### dual-eps fused tail — `muser_fused_norm_residual_rms_norm_32sg`: residual add + post-norm (eps 1e-8) + next norm (eps 1e-5) in one kernel; produces the next sub-block's normed input (Ch 10)
### MUSER_FERRITE_FFN_GATE_UP — opt-in (default OFF) fused `ffn_q4k_gate_up_silu_4r2s` FFN; opt-in because the pinned baseline packet regressed with it (`decode.rs:980-983`) (Ch 10)
### muser_scale_softcap_inplace — the fused tail kernel: ×logit_scale then tanh soft cap in one pass over the logits row (`muse_reference.metal:15`) (Ch 10)
### attention route ladder — per-layer kernel selection: llama-pinned vec / splitk / ferrite-interleaved, gated by `llama_vec_rows`/`llama_swa` predicates (`decode.rs:5646-5657`) (Ch 10)
### llama-pinned kernels — PSOs loaded from the prebuilt llama.cpp metallib (`MUSER_GGML_METALLIB`) so arithmetic matches the comparator bit-for-bit (Ch 10)
### KV store + memory barrier — the vec-route pattern: store the K/V row, `memory_barrier_with_resources`, then attend (Ch 10)
### command-buffer amortization — the whole 52-layer token recorded onto one concurrent encoder, committed once per token (`decode.rs:5448-5458`) (Ch 10)
### residual relay — the two-buffer residual stream: `activations.normed` carries the residual, `activations.post_norm` the normed sub-block output; the last tail writes `activations.hidden` (`decode.rs:5546-5548`) (Ch 10)
### Activations pool — the per-sequence GPU buffers of Table 10.2, allocated once, reused every token, zero hot-path allocation (`decode.rs:897`) (Ch 10)
### MetalKvPlane — one layer's K+V f16 buffer pair plus explicit ring metadata: capacity, len, origin_logical, origin_physical, head_major (`decode.rs:182`) (Ch 10)
### origin_logical / origin_physical — the ring's logical start vs its physical slot; placement is never derived from absolute position (Ch 10)
### CacheDiscontinuity — the fail-closed error when a KV append position is not exactly `origin_logical + len` (`decode.rs:265-284`) (Ch 10)
### DFlash — the five-layer speculative draft assistant of Ch 8; reads target hidden states at pinned layers, drafts up to the verify length (Ch 10)
### begin/finish_dflash_verify_suffix — the Mirror-SD split: run the verify block to a capture layer synchronously, submit the suffix layers + LM head without waiting (`decode.rs:3298, 3635`) (Ch 10)
### CPU-side exact acceptance — speculative tokens accepted/rejected on the CPU against the target's full distributions (`verify_full_speculative_mt_ordered`, `sampling.rs:1033`) (Ch 10)
### MetalSpeculativeCheckpoint — transactional KV protection: NoPE planes rewind metadata only; SWA planes retain the ≤16 rows a block may overwrite (`decode.rs:213-226`) (Ch 10)
### remote KV install — `begin_remote_kv_install`: build detached planes, scatter received tiles, validate, then atomically swap into live decode (`decode.rs:1852-1994`) (Ch 10)
### detached generation — a full replacement state built alongside live decode; swapped in only after the handoff seal validates (Ch 10)
### Handoff V2 — the authenticated mTLS + HMAC-sealed tile transport from the GX10 producer (Part VI) (Ch 10)
### NoPE tiles during prefill — the transfer schedule streaming the 13 position-free NoPE tiles (~6.5 MiB per 512 tokens) while CUDA prefill runs (`schedule.rs:1-21`) (Ch 10)
### PREFILL_BATCH_TOKENS / MAX_TEACHER_FORCED_TOKENS — the 512-row idle-prefill chunk that shrinks to 64 rows once a decode waits (`decode.rs:53-54`) (Ch 10)
### dispatch gap (+196) — the reconciled 760-vs-564 closure delta (104 norm-boundary + 39 SWA staging + 52 KV-publication + 1 copy); every cheap removal changes bits (Ch 10)
### PhaseProfiler closures — the one-command-buffer-plus-wait units the dispatch gap counts; profiling closures, not raw Metal dispatches (Ch 10)
