# Glossary seeds — Part VIII (Chapters 38–40)

Seed entries for the book glossary, one line each, in chapter order. To be
merged into `glossary.md` by the glossary owner; anchors follow the
glossary's slug convention.

### parity ledger — the append-only campaign ledger (`docs/goal-parity-ledger-2026-08.md`) whose entries record hypothesis, change, exactness gate, verdict, and receipt paths (Ch 38)
### comparator golden — the pinned llama.cpp byte artifact that gates exactness (since J0: the complete 808,192-byte f32 logit row, SHA-256 `fc37487b…`) (Ch 38)
### anchor flip — the J0 operator revision that retired Muser's self-referential production hash and made llama's own bytes the exactness gate (Ch 38)
### interleaved A/B — measuring both engines in the same session, rep by rep, so machine-state noise is common-mode and cancels in the ratio (Ch 38)
### ratio convention — all throughput ratios in this book are `llama ÷ muser`; above 1.0 means Muser wins (Ch 38)
### exact-token gate — a performance rep counts only if the two engines produced byte-identical tokens; divergent outputs mean different work, not different speed (Ch 38)
### teacher-forced — a timing mode that feeds each engine the correct previous token so per-token cost is comparable independent of sampling (Ch 38)
### adjacent lease window — measuring two lanes back-to-back under one held accelerator lease so drift between them is bounded by seconds (Ch 38)
### five-rep mean — the campaign's unit of evidence: five counted repetitions after the stated warmup convention, reported as mean with coefficient of variation (Ch 38)
### single-rep diagnostic — a one-sample cell marked `†` that never joins a matrix and cannot support a claim (Ch 38)
### synthetic fixture — a deterministic fixed prompt (period-8 cycle of 9 token ids) enabling exact cross-engine comparison; predictable from token identity alone (Ch 38)
### natural-text cell — a real-corpus measurement standing alongside the synthetic matrix since the half-window bug; cross-engine outputs may diverge, so speed stands without an exactness gate (Ch 38)
### accounting-invariant metric — a timing column defined identically across engines (wall time at 131,008 is one; short-output decode is not) (Ch 38)
### accelerator lease — the exclusive `/tmp/ferrite.gpu.lock` flock held by `accelerator_safe.py` around every GPU run, with quiet periods and process checks on both sides (Ch 38)
### fail-closed — a design where a check that cannot prove the good state stops the system before the unproven state passes for a proven one; the evidence is wrong until proven otherwise (Ch 39)
### release lock — `release/release-lock.json`, the authoritative single file whose containment state disables seals, candidates, and publication regardless of evidence strength (Ch 39)
### findings register — `release/findings-v1.json`, the zero-waiver defect list; release requires zero open findings (Ch 39)
### feature contract — `release/feature-contract-v1.json`, the frozen scope/hardware/policy file that (with findings and the lock) constitutes the campaign identity (Ch 39)
### readiness receipt — the single receipt issued only after all findings are closed and every unsealed lane report belongs to the exact campaign identity (Ch 39)
### atomic seal bundle — the final-campaign output: all lanes freshly rerun into a hidden directory, fsynced, then exposed with one rename; failure exposes nothing (Ch 39)
### launch-claims register — `docs/launch-claims.md`, the table every piece of launch copy must be checked against; a number with no row does not ship (Ch 39)
### OPERATOR REVIEW REQUIRED — the register tier for evidence-backed proposed wording that stays dead until the owner approves it, even if its reproduction gate passes (Ch 39)
### honesty tags — per-field labels on telemetry and claims: `measured` / `target` / `mock` (metrics schema) plus `[precedent-7B-ferrite]` and `[roadmap]` in the claims legend (Ch 39)
### mock — the honesty tag for a field with no backing measurement; the dashboard renders it unavailable and historical Ferrite results are never inserted as live Muser metrics (Ch 39)
### documentation truth pass — the audit genre that re-reads claim-bearing documents against implementation and retained receipts (Ch 39)
### notarial vs non-notarial — sealed, independently reproducible release evidence versus unsealed engineering evidence; everything in the 2026-08 campaign is `seal_eligible: false` (Ch 39)
### append-only evidence volume — `muser-receipt://`, where receipts are immutable (created by exclusive temp+fsync+rename, never replaced) and records journal O_APPEND (Ch 39)
### operational state — replay ledgers, sockets, locks: state that must live on the internal disk because the evidence volume's fsync tail poisons TTFT (Ch 39)
### SUPERSEDED banner — the correction written on the artifact itself when a document's numbers are invalidated; history is preserved, never edited (Ch 39)
### red-team pass — self-audit by independent reviewers (ledger forensics, receipt recompute, statistics, framing) that certifies the evidence, not the decision built on it (Ch 39)
### falsified-hypothesis ledger — the closing record of what was measured and rejected, each entry carrying hypothesis, experiment, receipt, verdict, and what the rejection preserves (Ch 40)
### all-accept control — a positive-control run with forced acceptance (110.59 tok/s distributed lane); never a serving result (Ch 40)
### verifier-only ceiling — output tokens divided by verifier wall alone, granting zero cost to everything else; the decisive rejection bound for distributed speculation (Ch 40)
### preregistered bar — a performance threshold fixed before the deciding runs (e.g. ≥ 99.151 % IID per-edge acceptance; the 200 ms GPU verifier gate) (Ch 40)
### Fallback B — the shipped product contract: native NVFP4 lane with plain decode only, speculation kquant-only, native+DFlash fail-closed structurally (Ch 40)
### negative fixture — a known-bad implementation retained to guard a contract (the 104-group fusion whose logits changed) (Ch 40)
### INVALID_WRONG_REASON — the label for a run that failed for reasons outside its hypothesis; retained, named, and not retried into a verdict (Ch 40)
### content-sensitive envelope — the published form of the NVFP4 quality result: gates are content- and depth-local, and the docs@65,536 exceedance is part of the claim (Ch 40)
